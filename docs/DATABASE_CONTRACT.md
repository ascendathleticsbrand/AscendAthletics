# ASCEND database contract

Money is numeric(14,2) NGN naira; IDs are UUID. Private writes use service-role RPCs with p_actor, independently checked against staff_roles. profiles.id references auth.users.id; signup creates client profile and linked customer, never staff. staff_roles(user_id,role owner|assistant,permissions jsonb) is the only staff authority. Permissions allow only boolean manage_packages/manage_delivery_rates flags; owners may grant these to assistants, and all financial/bank/staff authority stays owner-only. No frontend-supplied role is trusted.

Catalog: categories(id,name,slug,sort_order,active); products(id,category_id,name,slug,description,price,cost_price,status draft|coming_soon|active|unavailable,featured,size_guide); product_variants(id,product_id,sku,size,color,stock_on_hand,stock_reserved,stock_sold,stock_available generated,stock_confirmed_at,low_stock_threshold,is_low_stock generated); product_images(id,product_id,storage_path,alt,sort_order); collections(id,name,slug,description,banner_path,status draft|published|upcoming,launch_at); collection_products(collection_id,product_id). Confirmed stock is stock_confirmed_at IS NOT NULL.

People: profiles(id,full_name,phone); customers(id,profile_id nullable,name,email,phone); customer_addresses(id,customer_id,recipient_name,phone,state,city,area,address,landmark).

Orders: orders(id,order_number,customer_id,source website|whatsapp|instagram|in_person|other,customer_name,customer_email,customer_phone,fulfillment_method pickup|delivery,delivery_details jsonb,delivery_status pending|quoted|approved,delivery_fee nullable,subtotal,total_amount nullable,fulfillment_status pending|processing|ready_for_pickup|shipped|delivered|picked_up|cancelled,resolution_required,pay_later_authorized,reservation_expires_at,courier_name,tracking_reference). Guest token stored hashed and omitted from views. order_items(id,order_id,variant_id,product_name,sku,size,color,quantity,unit_price,unit_cost); stock_reservations(id,order_id,variant_id,quantity,status active|consumed|released|expired,expires_at). order_notes,fulfillment_events and immutable stock_movements hold history.

Finance: invoices(id,customer_id,order_id nullable,enrollment_id nullable,total_amount nullable,amount_paid,amount_refunded,outstanding_amount generated,payment_status pending|evidence_submitted|partially_paid|paid|rejected|refunded). payments(id,invoice_id,submitted_amount,amount_received,transfer_reference,bank_name,transferred_at,status pending|evidence_submitted|verified|rejected,bank_credit_reference unique nullable,verified_by,verified_at,notes,created_by). payment_evidence(id,payment_id,storage_path). refunds and immutable financial_adjustments preserve history. expenses(id,category,description,amount,spent_on,created_by).

Coaching: coaching_packages(id,name,mode physical|online,description,price,billing_model monthly|per_session|session_bundle|fixed_duration,duration_months default 1,duration_days nullable,session_count nullable,features jsonb,active). coaching_enrollments(id,customer_id,package_id,package_name,mode,billing_model,price,duration_months,duration_days,session_count,status requested|active|expired|cancelled,start_date,expiry_date,sessions_used,training_preferences jsonb {goal,schedule},pay_later_authorized,activated_by). coaching_session_usage holds sessions; coaching_enrollment_notes(id,enrollment_id,body,created_by,created_at) holds append-only staff-only administrative notes. Snapshot fields preserve enrollment terms.

Settings singleton business_settings(id=1,bank_name,bank_account_number,bank_account_holder,payment_instructions,pickup_location,pickup_instructions,pickup_contact,pickup_hours,contact_email,whatsapp_number,instagram_url,timezone Africa/Lagos,reservation_minutes 60,reminders_enabled false,reminder_days jsonb [7,2,0]); delivery_rates(id,state,city nullable,area nullable,fee,active); site_content(id,section unique,title,body,image_path,data jsonb,published).

Marketing: newsletter_subscribers(id,email unique,name,status subscribed|unsubscribed,unsubscribe_token_hash); immutable marketing_consents(id,subscriber_id,action opt_in|opt_out,source,policy_version); campaigns(id,name,subject,body_html,status draft|approved|sending|sent,approved_by,approved_at,created_by); campaign_recipients(id,campaign_id,subscriber_id,status,provider_message_id,locked_at,first_attempt_at). notifications(id,enrollment_id nullable,customer_id nullable,order_id nullable,invoice_id nullable,kind,scheduled_for,dedup_key unique,payload jsonb,status pending|sending|sent|failed,provider_message_id,last_error,locked_at,first_attempt_at,sent_at,created_at). audit_logs append-only. rate_limits(key,window_start,hits).

## Exact service-only RPCs

Returns JSON unless noted. Optional args can be omitted. Each mutation returns its updated primary record except composite returns indicated.

- create_checkout(p_items jsonb,p_customer jsonb,p_fulfillment_method text,p_delivery_details jsonb default '{}',p_actor uuid default null,p_source text default 'website',p_pay_later boolean default false) => {order,invoice,guest_token}; items [{variant_id,quantity}], customer {name,email,phone}. Server prices and delivery fees authoritative; unknown delivery fee leaves null total pending quote.
- guest_order(p_token text) => {order,items,invoice,payments,bank_details}; excludes token hash, staff notes, evidence paths, verification notes. Returns null invalid. Bank instructions withheld if delivery not approved.
- submit_payment(p_invoice_id uuid,p_amount numeric,p_transfer_reference text,p_bank_name text default null,p_transferred_at timestamptz default null,p_proof_path text default null,p_actor uuid default null,p_guest_token text default null).
- verify_payment(p_payment_id uuid,p_amount_received numeric,p_bank_credit_reference text,p_actor uuid,p_note text default null) => {payment,invoice,order}; owner only, unique actual-credit reference, transactional stock consumption or resolution flag.
- reject_payment(p_payment_id uuid,p_actor uuid,p_note text).
- record_stock(p_variant_id uuid,p_kind text,p_quantity integer,p_actor uuid,p_note text default null,p_resellable boolean default false); opening/reconciliation are absolute counts; restock/adjustment/damaged/return are deltas. Negative restricted adjustments owner only; return requires confirmed resellable.
- expire_reservations() => integer; expire_enrollments() => integer uses the configured business timezone; cancel_order(p_order_id uuid,p_actor uuid,p_reason text); resolve_order_stock(p_order_id uuid,p_actor uuid,p_note text) owner-only after restock/conflict review; update_fulfillment(p_order_id uuid,p_status text,p_actor uuid,p_courier_name text default null,p_tracking_reference text default null).
- quote_delivery(p_order_id uuid,p_fee numeric,p_actor uuid); approve_delivery(p_order_id uuid,p_guest_token text default null,p_actor uuid default null); authorize_pay_later(p_invoice_id uuid,p_actor uuid,p_note text).
- request_enrollment(p_package_id uuid,p_actor uuid,p_customer_id uuid default null,p_preferences jsonb default '{}') => {enrollment,invoice}; staff may select manual customer, clients always self.
- activate_enrollment(p_enrollment_id uuid,p_start_date date,p_actor uuid); record_coaching_session(p_enrollment_id uuid,p_session_date date,p_actor uuid,p_note text default null); renew_enrollment(p_enrollment_id uuid,p_actor uuid) => new {enrollment,invoice}; calendar_expiry(p_start_date date,p_months integer) => date.
- record_refund(p_payment_id uuid,p_amount numeric,p_reason text,p_external_reference text,p_actor uuid); financial_summary(p_actor uuid,p_from date default null,p_to date default null) => JSON.
- inventory_summary(p_actor uuid) => {physical_stock,reserved_stock,available_stock,sold_stock,unconfirmed_stock,low_stock}; staff-only actor validation, aggregate all variants in PostgreSQL. Physical/reserved/available/sold sums include only confirmed stock. Counts include every unconfirmed/low-stock variant, independent of API row limits.
- update_business_settings(p_changes jsonb,p_actor uuid); set_staff_role(p_user_id uuid,p_role text,p_permissions jsonb,p_actor uuid); revoke_staff_access(p_user_id uuid,p_actor uuid,p_note text) => {user_id,revoked}; last-owner removal is blocked and identities/history remain. link_guest_customer(p_actor uuid,p_guest_token text) requires verified matching auth email and secure guest token.
- subscribe_newsletter(p_email text,p_name text default null,p_source text default 'website',p_policy_version text default '1.0') => {subscriber_id,unsubscribe_token}; unsubscribe_newsletter(p_token text); unsubscribe_subscriber(p_subscriber_id uuid) for verified server HMAC links; approve_campaign(p_campaign_id uuid,p_actor uuid).
- check_rate_limit(p_key text,p_limit integer,p_window_seconds integer) => boolean.
- enqueue_transactional_notification(p_kind text,p_customer_id uuid,p_order_id uuid default null,p_enrollment_id uuid default null,p_invoice_id uuid default null,p_dedup_key text default null,p_payload jsonb default '{}') => void; service-only internal helper used inside the business RPC transaction. Allowed transactional kinds: order_created, enrollment_requested, payment_verified, enrollment_activated.

Checkout, enrollment requests/activation and owner payment verification insert notifications in the same transaction as their business records. Keys are order_created:<order UUID>, enrollment_requested:<enrollment UUID>, enrollment_activated:<enrollment UUID> and payment_verified:<payment UUID>. Payment payloads preserve received amount and invoice balance at verification time; later payments/refunds do not rewrite an earlier event. Order payloads preserve order_number, invoice_id, total_amount (nullable while delivery is unapproved) and delivery_status. Request payloads preserve package_name, invoice_id and total_amount; activation payloads preserve package_name/start_date/expiry_date.

Notifications are staff-readable only. Plaintext guest tokens, token hashes, bank-credit references and staff notes are prohibited in transactional payloads. The server may attach guest_token_encrypted after checkout to support a secure email order link. This attachment is optional and separate from durable event creation; the dispatcher sends no secure guest link until encrypted token data is available and valid. Provider retries claim pending/failed rows conditionally and use dedup keys for idempotency. first_attempt_at retains the first provider attempt across later failures and locks. Automated retries stop after 23 hours to stay inside the provider idempotency window. Migration 14 conservatively backfills legacy attempted rows from their earliest known creation/lock/send timestamp; unattempted pending rows stay null.

Private PostgREST computed fields coaching_enrollment_search(coaching_enrollments) and product_variant_search(product_variants) combine linked client contact/package and product name/SKU/size/color. Their unnamed row arguments prevent RPC exposure; only service_role may execute them. Database filters run before paging and exact counts, as supported by the official [PostgREST computed field documentation](https://docs.postgrest.org/en/stable/references/api/computed_fields.html).

Public RLS restricts catalog to active products with confirmed variants, scheduled collections, active coaching packages and published site_content. public_business_settings view exposes contact/pickup only. public_catalog view exposes sanitized product data. Clients see only linked customer records. Service-only RPCs validate actor rights. Assistants may prepare operational actions and marketing; only owner verifies money, grants pay-later exceptions, changes bank/roles or sends approved marketing.

Storage buckets product-images (public, staff write), payment-proofs (private, server upload; client reads only their linked evidence). Private proof paths are proofs/<invoice UUID>/<random UUID>.(jpg|png|webp). Guest evidence gets server signed URL only after secure token validation.

Only requested categories and safe setting defaults seeded. No invented product, inventory, client, package, financial or physical-address data.

Calendar expiry is an exclusive renewal boundary, start plus configured calendar months clamped to month end. Preferences allow only brief goal/schedule strings, each at most 500 characters. Customer profile changes synchronize linked customer name/phone. Test results and owner bootstrap: supabase/README.md. The automated WASM tests verify migration SQL and role policies with minimal Auth/Storage fixtures; real Supabase HTTP, Auth email flows, Storage upload/signing and multi-connection PostgreSQL concurrency remain separate launch checks.
